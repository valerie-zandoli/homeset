# HomeSet

HomeSet turns one sentence into a numbered at-home workout plan.

Example:  "I have 20 minutes, a mat, and dumbbells.  Work on legs."

HomeSet is a single-role AI agent built by Valerie Zandoli and Yadan Taino for Pursuit L2 Cycle 2.

- **Spec:**  [HomeSet Agent PRD](https://docs.google.com/document/d/1aQLT7d2mdhh-Bz-7_5RyaNbPUfcpwV9hcpnmFPKgIxQ/edit) (the Google Doc is the source of truth; this repo follows it)
- **Design:**  `docs/architecture-v4.png` (as built, drawn from the code on 2026-10-19), `docs/architecture-v3.png` (the design before the build) and `docs/architecture-v1.png` (simple)
- **Data:**  the free [wger](https://wger.de/en/software/api) exercise database (read-only)
- **Pitch:**  `docs/pitch-script.md` (the design pitch for 2026-10-19, with timing and the cut order)
- **Access:**  `docs/access-register.md` (every grant, the job step that needs it, where each limit is enforced in code, and the open gaps)

## Who it is for

HomeSet is a workout planner for the at-home fitness industry.  Its user is a busy adult who works out at home in a short window (the PRD targets 20 to 30 minutes) with whatever equipment they own.  One plain-language request goes in; one numbered plan comes out, built only from exercises in the wger database.

## Out of scope (version 1)

- **Medical advice.**  HomeSet never diagnoses, treats, or trains through pain.  Pain, injury, surgery, pregnancy, or a medical condition gets one fixed hand-off sentence from code, and no plan.
- **Timed moves**, such as planks.  wger does not mark which exercises are timed, so every exercise is counted by reps.
- **Accounts, sign-in, and a separate approver role.**  The person at the terminal is the user and the approver (version 2).
- **Any model tool beyond two.**  The model can search wger and add up time; it has no email, calendar, file, shell, or web access (`docs/access-register.md`).
- **Workout history.**  HomeSet keeps one saved plan, replaced only by a typed "yes".

```bash
git clone https://github.com/valerie-zandoli/homeset.git
cd homeset
python3.12 -m venv .venv
```

## Run

```bash
python -m pytest                                   # no key or network needed
python -m homeset "I have 20 minutes, a mat, and dumbbells.  Work on legs."
```

## How it fits together

```
user message
    |
    v
safety check in code ----- hand-off sentence or one fixed question -----> user
    |  (no trigger)             (the model is not called)
    v
model + system prompt ----- tool call -----> tool runner -----> wger
    |   ^                                                          |
    |   +----------- clean results (context feeding) <-------------+
    |
    +-- its own fixed message (question, error) ----------------------> user  (skips the checks)
    |
    v
"(assumed)" marker, written by code
    |
    v
output checks (plans only) ----- pass -----> user
    |
    +-- fail: back to the model once; a second failure is a visible error and no plan

save and swap (the command line, outside the model):
user types "yes" at a terminal -> saved_plan.json -> a later --saved run -> model, once, as data
```

The same picture with every box and the loops is `docs/architecture-v4.png`.

- The model picks labels from fixed lists (`FOCUS LABELS`, `EQUIPMENT LABELS`); code turns them into wger numbers.  The model sends no numbers; the results it reads carry each exercise's wger `id` and `equipment_ids` (and the filter), which the checks use.
- Code adds `language=2`, always adds bodyweight (equipment 7), repeats a filter once per value, follows the next-page link, and marks any cut list ("showing 40 of 56").
- Every plan passes five checks before the user sees it:  exact format, names from wger, equipment the user has, total within 5 minutes, safety line.  One failed check sends the plan back once; a second failure shows a visible error and no plan.
- Clear safety words (pain, injury, surgery, pregnancy, a medical condition) are checked in code over the whole conversation before the model is called, and fire the exact hand-off sentence.  Vague wording ("feels off", "bothering me", "twinge", "tender", "achy", a negated "does not feel right") is checked in code on the latest message and fires one fixed question, "Is that ordinary soreness or tiredness, or does it hurt?", without calling the model (Yadan's decision of 2026-10-15: a question, not a hand-off; `homeset/triggers.py:find_vague`).  "Sore" and "tired" do not fire.  The answer turn reaches the model together with the earlier request; an answer with a clear trigger is handed off by code; a second vague message after the question is handed off.  This answer turn exists in multi-turn runs only (`run_conversation` in `homeset/agent.py`, used by the evals).  The command line takes one request per run, so after the question a person runs a new command with the fuller request, and the earlier request is not carried over.  The prompt's step 1 stays as the second layer.  Both word lists are finite, so unusual phrasing ("acting up") still reaches the model.
- A request stops at 10 tool calls.
- A wger failure is never reported as "no exercises".  An unreachable service, a 200 that is not a results page, a page whose names cannot be read, and a search that outlasts 30 seconds all end as the same tool error and the same fixed sentence ("I could not reach the exercise database"); the reason is saved with the run (`tool_errors`).  "No exercises" is said only when wger returned a readable page with zero results.  The retries are safe because every call is a read; if a write tool is ever added (saving a plan), it needs an idempotency key and a read-back before any retry.
- Guarantees are tested in code with no model (`tests/test_guarantees.py`):  only labels reach wger, only GET requests leave, only wger links are followed, and every free-text field except the name is dropped; a name must also pass a character, length, and word filter, so a short injected instruction cannot pose as an exercise.  A name that implies gear the user did not name (TRX, machine, medicine ball, decline bench) is dropped too, whatever wger's equipment tag says.
- A reply that carries any plan marker (a "HomeSet plan:" line, a numbered exercise line, or a "Total time:" line) is checked as a plan, never waved through as a question; only the exact hand-off sentence skips the checks without being tested for markers.
- Every failure found live gets a row in `docs/regressions.md` and a test or case in the same commit as the fix.
